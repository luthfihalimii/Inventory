# Implementasi revisi ENT Inventory — 24 November 2026

## Ringkasan perubahan

- Floating cart untuk akun USER dengan jumlah unit keranjang dan pembaruan langsung setelah quick-add AJAX.
- Pembatalan PENDING dapat dilakukan langsung oleh USER; ADMIN/Korlab juga dapat membatalkan PENDING dan APPROVED dengan alasan wajib.
- Pembatalan APPROVED oleh USER menggunakan tabel `loan_cancellation_requests`. Status utama pengajuan tetap APPROVED selama permohonan menunggu keputusan; daftar menampilkan label `PERMOHONAN PEMBATALAN`.
- ADMIN/Korlab dapat menyetujui atau menolak permohonan pembatalan. Persetujuan membatalkan pengajuan, melepas unit RESERVED, mencatat histori dan audit. Penolakan mempertahankan status APPROVED dan menyimpan catatan keputusan.
- Penyerahan barang (BORROWED) diblokir selama permohonan pembatalan masih PENDING.
- Export menyediakan CSV dan halaman laporan siap cetak PDF melalui satu dropdown. Halaman PDF menggunakan format laporan landscape, identitas ENT, ringkasan, tabel, waktu cetak, dan footer. Browser menampilkan dialog cetak; pilih **Save as PDF / Simpan sebagai PDF** untuk menghasilkan berkas PDF.
- SOP pengembalian ditambahkan berdasarkan bagian penggunaan/pengembalian dan keterlambatan/kendala pada draft SOP yang telah tersedia di `resources/views/pages/sop.blade.php`.
- Pesan validasi berbahasa Indonesia, instruksi error yang lebih jelas, dan halaman error 403/404/419/500.
- Filter utama menggunakan input pencarian dengan suggestion list yang terhubung ke nilai dropdown asli.
- Direktori anggota diurutkan ascending berdasarkan nama generasi, nama divisi, lalu nama anggota; filter generasi dan divisi juga tersedia.
- Ornamen visual ringan, hover state, dan floating cart responsif ditambahkan.

## Migrasi

```bash
php artisan migrate
```

Migrasi baru: `2026_11_24_000001_create_loan_cancellation_requests_table.php`.

Jangan gunakan `migrate:fresh` pada database yang sudah berisi data.

## Alur pembatalan

| Status pengajuan | USER | ADMIN/Korlab |
|---|---|---|
| PENDING | Batalkan langsung | Batalkan dengan alasan |
| APPROVED | Ajukan permohonan; menunggu keputusan | Batalkan langsung dengan alasan jika belum ada permohonan aktif; atau proses permohonan USER |
| BORROWED dan setelahnya | Tidak dapat membatalkan | Tidak dapat membatalkan |

Ketika permohonan USER disetujui, sistem mengubah status utama menjadi CANCELLED dan melepas alokasi unit yang masih RESERVED. Ketika ditolak, status utama tetap APPROVED. Unit tidak dapat diserahkan selama permohonan masih menunggu keputusan.

## Penyempurnaan filter real-time

- Filter daftar anggota, inventaris, unit inventaris, pengajuan peminjaman, pengembalian, audit log, dan rentang tanggal dashboard diterapkan otomatis tanpa menekan tombol Filter/Terapkan.
- Pencarian teks memakai jeda 350 ms setelah pengguna berhenti mengetik agar tidak mengirim permintaan pada setiap karakter.
- Perubahan dropdown searchable dan tanggal langsung menerapkan filter.
- Filter tetap diproses di server sehingga hasil, jumlah data, dan pagination mengikuti query yang aktif.
- Setiap perubahan filter mengembalikan pagination ke halaman pertama.


## Pembaruan tambahan — foto pengembalian, identitas anggota, dan pemisahan transaksi

- Foto kondisi barang pada pengajuan pengembalian sekarang wajib dilampirkan. Pengguna dapat memilih beberapa foto sekaligus dalam satu input `multiple`, lalu mengirim seluruh foto bersama formulir pengembalian.
- Minimal 1 foto dan maksimal 10 foto per pengajuan; format yang diterima JPG/JPEG, PNG, dan WEBP dengan batas 5 MB per foto.
- Halaman pengembalian menampilkan petunjuk bahwa seluruh foto harus dipilih sekaligus sebelum formulir dikirim. Validasi backend tetap menjadi pengaman utama.
- Pengaturan akun menampilkan identitas `kode anggota · nama anggota` agar USER dapat melihat kode nama yang terhubung ke akunnya.
- Halaman pengajuan peminjaman dipisah menjadi tiga tabel: **Transaksi berlangsung** (PENDING, APPROVED, BORROWED, RETURN_PENDING, RETURN_ISSUE), **Success history** (hanya COMPLETED), dan **Riwayat tidak dilanjutkan** (REJECTED, CANCELLED). Pemisahan ini menjaga transaksi yang ditolak/dibatalkan tetap dapat ditelusuri tanpa mencampurkannya dengan success history.
- Pencarian transaksi juga mencakup kode anggota selain kode pengajuan dan nama anggota.
- Ketiga tabel memiliki pagination terpisah dan tetap mempertahankan filter yang sedang aktif.
